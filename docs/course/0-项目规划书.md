## 1 项目概述

BaiduNetGo 是一个百度网盘桌面客户端，支持 macOS、Windows 和 Linux。界面用 MyGo 框架的原生 `ui` 包在 GPU 上直接绘制，不带浏览器内核；网盘能力来自把开源项目 BaiduPCS-Go 当作库使用，加上直接调用 pan.baidu.com 的 Web 接口。

项目的开发方式本身也是规划的一部分：代码几乎全部由 AI 编程助手（Claude Code，模型 Opus 5.5）编写，本人负责提出需求、判断好坏、验收和取舍。

## 2 项目背景

百度网盘用户量大，但官方桌面客户端有几个长期问题：

| 问题 | 具体表现 |
|---|---|
| 限速 | 不开会员被限速；开了会员，默认的连接数和分块也不一定能跑满 |
| 臃肿，元素混杂 | 界面里广告、推荐、活动入口很多；客户端基于浏览器内核，体积和内存都大 |
| 使用不够优雅 | 看一张图、一份 PDF 也要先下载；别人发来的分享链接要复制、打开网页、输提取码、再转存 |
| 复古体验拉满 | Linux 版更新慢、界面陈旧；10 月的新版本在 Arch Linux 上装完打不开，从托盘退出后托盘图标还留着 |

开源的 BaiduPCS-Go 功能强，但只有命令行。本人 5 月起曾用 Rust 写过终端版 baidupcsr（104 次提交），这次改做图形界面，从头开始。

## 3 项目目标

1. **原生、轻**：不带浏览器内核，安装包控制在十几 MB 以内，界面流畅。
2. **不下载就能看**：图片、PDF、代码、Markdown、音乐直接在内存里预览，视频交给 mpv 播放，不写磁盘。
3. **传输参数自动调优**：按会员等级实测下载线路、连接数、块大小、同时传输数、上传连接数，不让用户猜。
4. **分享链接顺手**：复制别人的分享链接后自动打开预览，勾选要的文件转存。
5. **三平台一份代码**：纯 Go、不用 cgo，一台电脑交叉编译 macOS、Windows、Linux。
6. **工程上可持续**：每次推送自动测试、升版本、打三平台安装包并发布。

## 5 技术方案

| 层面 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.27 | 并发适合大量网络 I/O；单文件二进制；交叉编译方便 |
| 界面 | MyGo `ui` 包（立即模式，GPU 绘制：Metal / Direct3D 11 / OpenGL） | 不套网页壳；纯 Go；界面能在没有窗口时测试 |
| 网盘协议 | BaiduPCS-Go 作为库 + 直接调用 Web 接口 | 下载直链、上传复用成熟实现，其余接口直接调用更灵活 |
| PDF | PDFium 编译成 WebAssembly，用 wazero 运行 | 不需要 cgo，三平台一致 |
| 视频 | 外部 mpv，经本地回环代理读取 | 百度下载服务器只接受有界 Range，代理把播放器的请求切成小块 |
| 特效 | MyGo 着色器（Kage） | 删除、上传时的粒子动画在 GPU 上算 |

实测数字（Apple M4，Go 1.27.3）：

| 指标 | 数值 |
|---|---|
| 动画中每帧耗时 | 中位 0.3 ms，90% 在 0.6 ms 以内；窗口静止时 CPU 0% |
| 增量编译 / 从零全量编译 | 约 1 s / 不到 10 s |
| 整个开发环境 | 不到 1 GB（Go 工具链 270 MB + 依赖 225 MB + 编译缓存 343 MB） |
| Windows 安装包 | 10.7 MB（含 PDF 引擎） |

架构、模块和关键设计见《设计说明书》。

## 6 开发方法

### 6.1 以 AI 为主力编码

| 角色 | 负责 |
|---|---|
| 本人 | 提需求、定技术路线和审美、试用、挑问题、做取舍、验收 |
| AI（Claude Code） | 读依赖源码、写代码和测试、自己跑测试和截图验证、提交推送 |

整个项目的需求文档是两句话：贴上 BaiduPCS-Go 和 MyGo 两个仓库链接，“这两个项目结合，给百度网盘搓一个美丽的客户端，要优雅，优雅的动画，优雅的逻辑，以及美丽的不落盘预览”，加上“用 go 原生前端”。初代版本只用了一个 Claude Pro 的 5 小时额度就完成。

### 6.2 保证 AI 写对的手段

1. **让 AI 自己验证**：自写假网盘 `internal/fakepan` 模拟百度全部接口和限制规则；50 个界面测试用 `ui.Tester` 驱动真实视图；窗口截图给 AI 自己看；真实账号自检。
2. **纠正过的事写进规则**：项目根目录的 `CLAUDE.md` 记录命令、架构和踩过的坑，每个会话启动时都会读到。
3. **小步提交、自动发布**：一件事一个提交；每次推送跑测试，通过才发版。

## 9 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 百度接口无文档、随时变化 | 功能失效 | 接口集中在 `internal/baidu`；假网盘 + 真实账号自检双重验证 |
| 账号被风控 | 无法使用 | 自检只在临时文件夹中进行并清理；测速上传从不合并，不留文件 |
| 凭据泄露 | 账号安全 | AES-GCM 加密 + 系统钥匙串；重新开启 TLS 证书校验；本地代理只听回环地址并带随机令牌 |
| AI 写出隐蔽错误 | 质量 | 每次改动都要有测试；出过的问题写进 `CLAUDE.md` |
| 汇报现场网络不稳定 | 演示失败 | 用内置假网盘离线演示（`BAIDUNETGO_FAKE=1`），不需要账号 |
| 第三方代码许可证 | 合规 | 移植代码保留 Apache-2.0 声明和 NOTICE |
