## 3 开发过程模型

采用**增量迭代 + 持续交付**：

- 每个迭代交付一组可用功能，每个功能是一个提交（“一件事一个提交”，提交说明写清改了什么、为什么改）。
- 每次推送到 `main` 自动跑测试并发布一个新版本，所以 `main` 永远是可发布状态。
- 开发循环（每个功能都走一遍）：

```
提出需求/问题 → AI 读代码给出方案 → 人确认方向 → AI 实现并写测试
     ↑                                                    ↓
  下一个需求 ← 提交并自动发版 ← 人审查、试用 ← 测试/截图/自测验证
```

## 5 配置管理

| 项 | 做法 |
|---|---|
| 版本控制 | Git，GitHub 私有仓库；主干开发（`main`） |
| 提交规范 | 一个提交只做一件事；提交说明是一句完整的话，写明改了什么和为什么 |
| 版本号 | 语义化版本；默认每次推送升补丁位，提交说明中写 `#minor` / `#major` 升次版本/主版本 |
| 发布 | GitHub Actions：测试 → `tools/release` 计算版本号并写 CHANGELOG → 打 tag → 构建 Linux/Windows/macOS → 发布 Release |
| 变更记录 | `CHANGELOG.md` 自动生成，按“新增/修复/改进”分组 |
| 文档变更 | 只改 Markdown 或 `docs/` 不触发发版 |
| 项目知识库 | `CLAUDE.md`：架构、命令、踩过的坑，人和 AI 共同维护 |
| 并行会话 | 多个 AI 会话同时改同一仓库时，每个只提交自己改过的文件 |

## 6 质量保证

| 手段 | 内容 |
|---|---|
| 单元/集成测试 | 106 个测试函数；`internal/*` 各包有单元测试 |
| 界面测试 | 50 个，`ui.Tester` 驱动真实视图，后端是 `internal/fakepan` 假网盘，覆盖浏览、预览、文件操作、分享、传输、粒子动画等 |
| 视觉检查 | 测试可输出界面截图（`BAIDUNETGO_SNAPSHOTS`）；真实窗口截图（`BAIDUNETGO_CAPTURE`） |
| 真实环境自测 | `BAIDUNETGO_SELFTEST`：在真实账号的临时文件夹中逐项测试全部功能，结束后清理；下载的文件按网盘 MD5 校验；可附带测速 |
| 静态检查 | `go vet ./...`、`gofmt -l .`，提交前必须通过 |
| 交叉编译检查 | `CGO_ENABLED=0 GOOS=windows go build` |
| 持续集成 | 每次推送自动跑全部测试，失败则不发版 |
| 性能测量 | `MYGO_FRAME_STATS=all` 统计每帧耗时和 GPU 实例数 |
| 测试本身的审查 | 例：`TestPathFolds` 原来写死 1500 / 1250 px，Linux CI 的字体更宽导致失败；改成用二分法从测量值推导折叠宽度 |

## 7 风险管理

| 风险 | 可能性 | 影响 | 应对 | 结果 |
|---|---|---|---|---|
| 百度接口无文档、随时变化 | 高 | 高 | 接口集中在 `internal/baidu`；假网盘 + 真实账号自测双重验证 | 发现“只接受有界 Range”“分享者头像字段名不同”等隐藏规则并已处理 |
| 测试需要真实账号，难以自动化 | 高 | 中 | 自写假网盘模拟全部接口及限制规则 | 全部界面测试无需账号 |
| 账号被风控/封禁 | 中 | 高 | 自测只在临时文件夹中操作并清理；测速上传从不合并，不留文件 | 未发生 |
| 凭据泄露 | 低 | 高 | AES-GCM 加密 + 系统钥匙串；重开 TLS 校验；流代理只听回环地址 + 随机令牌 | — |
| 立即模式界面性能 | 中 | 中 | 帧统计测量、控制着色器实例数和每像素循环 | 动画中每帧中位 0.3 ms |
| AI 生成代码有隐藏错误 | 中 | 高 | 必须有测试与人工审查；每个坑写进 `CLAUDE.md` | 发现并修复死锁、动画停住、缓存失效等问题 |
| 多个 AI 会话互相覆盖 | 中 | 中 | 规则：只提交自己改的文件 | 未发生覆盖 |
| 第三方代码许可证 | 低 | 中 | 移植代码保留 Apache-2.0 声明与 NOTICE | 已处理 |
| 汇报现场网络不稳定 | 中 | 高 | 用假网盘离线演示（`BAIDUNETGO_FAKE=1`） | 已准备 |
