## 1 设计目标

1. **原生且轻**：界面由 GPU 直接绘制，不带浏览器内核；纯 Go，不用 cgo。
2. **界面永不卡顿**：所有网络操作在后台进行，界面线程只读状态。
3. **适应百度的限制**：下载服务器只接受有界 Range、链接会过期、会话会轮换，这些都在底层统一处理，上层不用关心。
4. **不用真实账号也能测**：自写假网盘，界面测试直接驱动真实视图。

## 2 技术选型

| 层面 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.27 | 并发模型适合大量网络 I/O；单文件静态二进制；交叉编译方便 |
| 界面 | MyGo `ui` 包（立即模式，GPU 绘制） | 无 WebView，体积小、启动快；纯 Go |
| 网盘协议 | BaiduPCS-Go 作为库 + 直接调用 pan.baidu.com Web API | 下载直链、上传、转存复用成熟实现；其余接口直接调用更灵活 |
| PDF | PDFium 编译成 WebAssembly，用 wazero 运行 | 不需要 cgo，三平台一致 |
| 视频 | 外部 mpv | 格式最全，不自己造解码器 |
| 特效 | MyGo 着色器（Kage 语言） | 粒子、光环等效果在 GPU 上算 |

## 5 关键设计

### 5.1 界面线程模型

立即模式界面每帧重新构建一遍视图。为了不卡顿、不出数据竞争，定了一条硬规则：

- `App` 持有全部状态，`App.View` 在主线程每帧运行，**只读状态**。
- 网络操作在 goroutine 中进行，结果通过 `a.update(fn)` 交回主线程执行（真实运行时是 `Window.Update`；测试中没有窗口，`fn` 入队，下一帧开头由 `runQueued` 执行）。
- 提示条、剪贴板需要 `*ui.Context`，所以后台代码只把它们排队（`a.toast`、`a.copy`），由视图在下一帧真正执行。

```
goroutine:  data, err := client.List(ctx, dir)
            a.update(func(){ a.listings[dir].files = data })   // 不直接改状态
main loop:  runQueued() → View() 读取 a.listings[dir] 绘制
```

### 5.2 阶段与路由

`App.phase`：启动中 → 登录 → 就绪。就绪后 `shell.go` 绘制侧边栏和标题栏，中间是 `ui.Router`：

| 路由 | 页面 |
|---|---|
| `/files/{path...}` | 网盘目录（路径段逐段 `url.PathEscape`） |
| `/search?q=` | 搜索结果 |
| `/transfers` `/shares` `/offline` `/recycle` `/settings` | 传输、分享、离线、回收站、设置 |

每个目录有自己的 `listing`（缓存在 `a.listings`，以目录为键），所以页面切换动画中滑出的旧页面仍显示它自己的文件。

所有模态框由一个 `a.dlg`（带 `dialogKind`）驱动；文件预览是单独的浮层 `a.pv`。图片预览与缩略图共享 `ElementTransition{Match: thumbMatch{fsid}}`，实现"从缩略图长出来、缩回去"的效果。

### 5.3 网盘客户端的两条路径

```
           ┌─ 库调用（BaiduPCS-Go） ─ LocateDownload 直链（需 uid，从贴吧接口取一次）
Client ────┤                        ─ 上传（internal/pcsport）、分享转存
           └─ Web API（pan.baidu.com） ─ 列表（web=1 带缩略图）、文件管理、回收站、
                                         分享、离线（cloud_dl）；写操作带 bdstoken
```

- `baidu.Open(creds)` 从 Cookie 建出客户端，不碰 BaiduPCS-Go 的全局配置，并**重新开启 TLS 证书校验**（该库默认关闭）。
- 客户端有自己的 HTTP 传输：按请求的 context 拨号、设超时、把连接分散到下载主机的多个地址上。
- errno −6/−4/111 统一映射为 `ErrNotLoggedIn`，上层收到即退回登录页。
- `baidu.OpenAt(creds, base)` 让客户端指向假网盘；少数绑定在库上的路径（直链、上传、转存）在 `c.fake()` 时换成假网盘友好的实现。

### 5.4 有界 Range 与 mpv 流代理

实测发现：百度下载服务器只接受 `bytes=a-b`；不带 Range 或 `bytes=a-` 返回 403。因此：

- 所有读取内容的地方（`remote` 预览读取、`transfer` 下载、`tune` 测速）都按块发有界请求。
- mpv 内部的 ffmpeg 会发开放式 Range，无法直接给它直链。于是设计了 `internal/stream`：

```
mpv ──GET bytes=1000-──▶ 127.0.0.1:随机端口/随机令牌 ──▶ 拆成若干 4 MB 有界请求
                          （internal/stream）          ──▶ 提前并发取 Ahead 块
                                                       ──▶ 链接过期时自动重新获取
```

### 5.5 传输管理器

- `Manager` 是一个队列，同时运行 `Parallel` 个任务。
- 下载：把文件切成固定大小的块（默认 4 MB，可被测速结果调整），用 `Threads` 个连接并发获取，写入 `<文件>.bngdl`；旁边的 `.bngdl.json` 记录已完成的块和块大小，用于断点续传。全部完成后改名。
- 上传：一次读文件同时算出整文件 MD5、CRC32 和分片 MD5，先尝试秒传，不行再分片并发上传。
- 任务状态持久化到用户数据目录的 `transfers.json`。
- `OnChange` / `OnFinish` 回调**在管理器的锁之外**调用（早期在持锁时调用造成过死锁，见 AI 心得文档）。
- 断网或休眠时任务排队等待；运行时阻止系统休眠。

### 5.6 自动调优算法

`internal/tune` 一项一项地测，每项都在前面已测出的最优值基础上进行：

1. 下载主机（`DownloadURLs` 返回所有候选主机，测速后用 `SetHosts` 排序）
2. 每个文件的连接数
3. 分块大小
4. 同时下载的文件数（加一个大文件并行测）
5. 上传连接数（向一个预创建但永远不合并的上传任务发随机分片，不留下任何文件）

推荐规则：在**最快速度的 90% 以内取最少的连接数**（只用未被拒绝的样本）；分块大小取 5% 以内最接近 4 MB 的；再推算播放器和预览需要的预读块数（足够 8 MB/s）。每个会员等级每周测一次，结果带 `Version`，算法升级后自动重测。用户手动设置只覆盖计数类参数，主机、分块、预读仍用测量值。

### 5.7 登录来源与凭据存储

```
启动 → 读取本地会话 session.enc ──有效──▶ 就绪
            │无/过期
            ▼
       用户未主动退出？──是──▶ 读官方 Linux 客户端的 Cookie（Electron 的 SQLite，自写纯 Go 读取器）
            │                  └─ 没有则读 BaiduPCS-Go 的 pcs_config.json
            ▼
         登录页（扫码 / 粘贴 Cookie / 手动导入链接）
```

- 会话用 AES-GCM 加密存于 `session.enc`；密钥放系统钥匙串（`mygo.Secrets`），没有钥匙串时退回 0600 权限的密钥文件。
- 钥匙串服务名固定为 `com.pengstem.baidunetgo`，开发版、`go run` 版和打包版共用；旧服务名下的密钥读到后迁移过来。
- Cookie 被网盘轮换、uid 首次获取时（`Client.OnChange`）和退出时都会重新保存。

### 5.8 不落盘预览

- `internal/remote`：`ReadAll` 带大小上限地把文件读进内存；`File` 是可 Seek 的读取器，带块缓存，用于边下边播音频。遇到 403 自动重新取链接。
- PDF：PDFium 编译成 wasm，由 wazero 运行；首次需要时才启动实例池（`pdf.Warm`）。macOS 加固运行时会杀掉 wazero 生成的代码，因此 `entitlements.plist` 授予 `allow-unsigned-executable-memory`。
- 视频及 MyGo 不能解码的音频：通过 `internal/player` 启动 mpv，带上网盘要求的 User-Agent 和 Cookie，经 5.4 的流代理读取。

### 5.9 文件进出动画与性能

- 删除的文件在列表中保留到"碎成粒子飘走"结束（`a.dying`，刷新列表时由 `keepDying` 保留）。
- 上传中的文件立即以负数 FsID 的行出现在目标文件夹，随上传进度由粒子"聚拢"成形（`a.gathers`）。
- 每个着色器绘制都是窗口无法合批的 GPU 实例，所以：大量小元素用普通填充；`specks.kage` 每个像素只检查能影响到它的格子，超出范围立即返回。结果：20 行同时删除，每帧绘制约 2 ms。
- 测试环境（`ui.Tester`）里着色器在 CPU 上解释执行，所以只在 `a.gpu` 为真时启用，并提供测试可见的普通回退效果。

### 5.10 可测试性设计

```
app/*_test.go ──ui.Tester 驱动真实视图──▶ App ──baidu.OpenAt──▶ internal/fakepan（httptest）
                                                              内存文件树：生成的图片、PDF、WAV
                                                              模拟有界 Range 规则、两台下载主机、
                                                              按列表重新签名的缩略图 URL
```

- 新增任何网盘接口，都要在 fakepan 中加对应端点。
- `BAIDUNETGO_SNAPSHOTS=dir` 让测试把界面截图写成 PNG，不开窗口也能检查视觉。
- `BAIDUNETGO_CAPTURE=out.png` 让真实窗口运行几秒后截图退出，脚本（以及 AI）可以"看到"界面。
- `BAIDUNETGO_SELFTEST` 用真实账号在一个临时文件夹里逐项测全部功能，结束后删除该文件夹。

## 6 数据设计

| 数据 | 位置 | 格式 | 说明 |
|---|---|---|---|
| 会话凭据 | 用户数据目录/`session.enc` | AES-GCM 密文 | Cookie、BDUSS、STOKEN、uid |
| 加密密钥 | 系统钥匙串（或 0600 密钥文件） | 32 字节 | |
| 设置 | 用户数据目录/`settings.json` | JSON | 下载目录、mpv 路径、连接数、预览上限、测速记录等 |
| 传输任务 | 用户数据目录/`transfers.json` | JSON | `Task{ID, Kind, Name, Remote, Local, Size, Done, State, Err, Created, Finished}` |
| 下载进度 | `<文件>.bngdl` + `.bngdl.json` | 二进制 + JSON | 未完成的数据与已完成块列表 |
| 缩略图缓存 | 内存 | | 以 fs_id + 修改时间 + 大小为键（URL 每次列表都会重新签名，不能做键） |

## 7 接口设计（网盘客户端主要方法）

| 类别 | 方法 |
|---|---|
| 账号 | `User` `Quota` `LoginInfo` `Credentials` `OnChange` |
| 浏览 | `List(dir, order)` `Search(dir, key)` |
| 下载 | `DownloadURL` `DownloadURLs` `SetHosts` `Fetch(url, off, n)` |
| 文件管理 | `Mkdir` `Rename` `Move` `Copy` `Delete` |
| 回收站 | `RecycleList` `Restore` `Purge` `EmptyRecycle` |
| 分享 | `CreateShare` `Shares` `SharePassword` `CancelShares` `SaveShare` |
